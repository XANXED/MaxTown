# MaxTown

MaxTown — MVP мини-приложения для MAX, которое помогает жильцам многоквартирного дома посмотреть состояние дома, найти контакты и подать Заявку Ответственному. В репозитории также есть панель Модератора, HTTP API и бот MAX.

## Пользовательский сценарий

Жилец открывает мини-апп MaxTown в MAX, просматривает карточки дома, Состояние дома, События дома, Контакты и свои Заявки. Экран создания Заявки предназначен для передачи сообщения об неисправности Ответственному. В текущем MVP экраны работают на локальных примерах: отправка и хранение Заявки на сервере ещё не реализованы.

Основной демонстрационный путь: запустить мини-апп, открыть его в браузере, выбрать заполненные примерами экраны через `?demo=filled`, просмотреть детали Заявок и Событий. Интеграция с MAX доступна через скрипт WebApp на странице и требует открытия опубликованного HTTPS-адреса внутри MAX.

## Состав и архитектура

- `apps/miniapp` — React + Vite, интерфейс Жильца для MAX; демонстрационные данные находятся в фикстурах.
- `apps/admin` — React + Vite, прототип панели Модератора.
- `apps/api` — Fastify API. Сейчас реализован только `GET /health`.
- `apps/bot` — бот на `@maxhub/max-bot-api`; отвечает приветствием на запуск.
- `packages/shared` — общие TypeScript-типы и контракты.
- `design` — токены оформления и темы MAX.

Постоянная база данных пока не подключена. Данные приложения не переживают перезапуск: интерфейсы используют локальные демонстрационные фикстуры, а API не сохраняет пользовательские данные.

## Запуск всех локальных компонентов в Docker

Требуются Docker Engine и Docker Compose v2. В корне репозитория выполните одну команду:

```bash
docker compose up --build
```

После сборки откройте:

- Мини-апп: <http://localhost:5173>
- Панель Модератора: <http://localhost:5174>
- Проверка API: <http://localhost:3000/health>

Команда запускает все локальные веб-компоненты и API. Бот MAX — внешний интеграционный процесс и включается при наличии токена:

```bash
docker compose --profile bot up --build
```

Либо сначала задайте `BOT_TOKEN` в `.env`, затем выполните эту команду. Без действительного токена MAX проверить работу бота нельзя.

Сборка использует `npm ci` и `package-lock.json`, Node.js 24 Alpine и одну общую установку зависимостей для npm workspaces. При обычном доступе к npm registry сборка рассчитана на выполнение в пределах пяти минут, кроме первоначальной загрузки базового образа.

## Параметры окружения и порты

Скопируйте `.env.example` в `.env` для локальной настройки. Секреты в репозиторий не добавляйте.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `API_PORT` | `3000` | Порт API на хосте при публикации Docker-порта |
| `BOT_TOKEN` | пусто | Токен бота, выданный Master Bot в MAX; нужен только для профиля `bot` |

| Компонент | Порт хоста | Назначение |
| --- | ---: | --- |
| API | `3000` (или `API_PORT`) | `GET /health` |
| Мини-апп | `5173` | Vite dev-сервер |
| Панель Модератора | `5174` | Vite dev-сервер |
| Бот | нет входящего порта | Подключается к MAX Bot API исходящим соединением |

## Зависимости и внешние сервисы

Зависимости JavaScript зафиксированы в корневом `package-lock.json`. Требуются Node.js 24 или новее для запуска без Docker, npm и Docker Compose v2 для контейнерного запуска.

Внешние сервисы:

- MAX WebApp Bridge — загружается мини-аппом с `https://st.max.ru/js/max-web-app.js`; для работы внутри MAX нужен доступ к сервисам MAX и зарегистрированное/опубликованное мини-приложение.
- MAX Bot API — используется ботом. Для его проверки нужен токен `BOT_TOKEN` от Master Bot и доступ к сети.
- npm registry — нужен для установки зависимостей при сборке образа.

Контейнеры сами по себе не публикуют продукт в MAX. Чтобы пройти сценарий именно внутри MAX, настройте мини-приложение и бота в MAX и укажите доступный MAX HTTPS URL для мини-аппа. Локальные адреса `localhost` предназначены для проверки в браузере на машине разработчика.

## Работа с данными и тестовые примеры

Тестовые примеры встроены в исходный код и не требуют загрузки дампа или запуска миграций. В мини-аппе фикстуры доступны в режиме разработки через параметр `?demo=filled`; панель содержит свои фикстуры регистраций. Текущий backend не предоставляет методы чтения и записи этих сущностей.

Данные в интерфейсе являются демонстрационными, включая имена, адреса и Заявки. Не вводите реальные персональные данные. Изменения не сохраняются при перезапуске.

## Пошаговая проверка

1. Убедитесь, что Docker Engine запущен.
2. Выполните `docker compose up --build` из корня репозитория.
3. Дождитесь сообщения Vite о доступности сервисов.
4. Откройте <http://localhost:5173/?demo=filled> и проверьте экраны и демонстрационные карточки.
5. Откройте <http://localhost:5174> и просмотрите демонстрационную панель.
6. Откройте <http://localhost:3000/health>. Ожидаемый ответ: `{"status":"ok"}`.
7. Для проверки бота задайте `BOT_TOKEN` и запустите `docker compose --profile bot up --build`; откройте чат бота в MAX и отправьте команду запуска. Ожидаемый ответ — приветствие MaxTown.

Тот же код можно запустить без Docker через `npm ci`, затем `npm run dev:miniapp`, `npm run dev:admin` и `npm run dev:api`. Типы проверяются командой `npm run typecheck`, тесты — `npm test`.

## Известные ограничения

- Это прототип интерфейсов, а не подключённая система управления Домом: регистрация, вход, проверка `initData`, создание Заявок и серверное хранение ещё не реализованы.
- API реализует только health-check; БД и миграций нет.
- Заполненные фикстуры предназначены для демонстрации и не являются реальными данными.
- Для бота требуется реальный токен MAX; профиль бота выключен по умолчанию.
- Для открытия мини-аппа внутри MAX необходимы публикация и настройки со стороны платформы MAX.
- Интеграции с ГИС ЖКХ, ФИАС/ГАР, картами и внешними справочниками в работающий код пока не включены.

## Остановка и повторный запуск

Остановить контейнеры: `Ctrl+C`, затем при необходимости выполнить `docker compose down`. Повторный запуск — `docker compose up` (или `docker compose up --build`, если менялся код/конфигурация). Постоянных томов нет, поэтому локальные данные контейнеров не требуется сбрасывать.
