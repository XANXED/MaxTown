# Как работают сервисы поиска интернет-провайдеров по адресу (Россия)

> Разбор на основе публичной информации агрегаторов (101 Интернет, ДомИнтернет и др.), агентских программ операторов и документации адресных сервисов. Состояние на сентябрь 2026.

---

## 1. Суть в одном абзаце

Такой сайт — это не «опрос провайдеров в реальном времени», а **собственная база соответствий `дом → провайдеры → тарифы`**. Адреса приводятся к единому справочнику (ФИАС/ГАР), провайдеры-партнёры регулярно присылают списки подключённых домов и тарифы, а сайт зарабатывает как **агент операторов**: пользователь оставляет телефон, заявка уходит провайдеру, агрегатор получает вознаграждение за подключённого абонента. Для пользователя сервис бесплатный.

```
[Пользователь вводит адрес]
        │  автокомплит (ФИАС/ГАР, DaData)
        ▼
[house_id (GUID дома)] ──► [coverage: провайдеры в доме] ──► [тарифы + акции]
                                                                   │
                                                  [Заявка: телефон + тариф]
                                                                   ▼
                                  [Колл-центр агрегатора] ──► [Провайдер: API / агентский портал]
                                                                   │
                                                  [Статус: подключён / отказ / нет ТВ]
                                                                   ▼
                                                     [Агентское вознаграждение]
```

## 3. Бизнес-модель: агентские программы

Весь рынок держится на том, что операторы платят за привлечённых абонентов.

- **МТС** — агентский договор-оферта заключается при регистрации в программе «МТС Агенты»; есть агентский портал и **автоматическая передача лидов из CRM агента в МТС**.
- **Билайн** — агентская программа (для B2B заявлено до 30% от абонплаты и разовых платежей).
- **Ростелеком** — публикует отдельную форму договора на «Домашний интернет» и ТВ для агентов.
- **МегаФон** — «Условия агентских соглашений B2C» с разделом о фрод-договорах (за фиктивные подключения вознаграждение не платится).

Что получает провайдер: дополнительные продажи из SEO-трафика агрегатора без своей рекламы. Что получает агрегатор: фиксированную выплату или процент за каждого **фактически подключённого** абонента (не за заявку).

Отсюда важная деталь: у агрегаторов почти всегда есть **свой колл-центр** — он дозванивается до клиента, уточняет адрес/квартиру, допродаёт ТВ/роутер и передаёт «готовую» заявку оператору. 101 Интернет прямо продаёт это как услугу, вплоть до лицензирования своей CRM для колл-центров.

## 4. Техническая архитектура

### 4.1. Адресный слой (самое важное)

Провайдеры присылают адреса в хаотичном виде: `пр-т Просвещения 15к2`, `Просвещения пр., д.15, корп.2`, `пр. Просвещения, 15 лит. А`. Чтобы это матчилось с вводом пользователя, всё приводится к одному идентификатору дома.

**ГАР / ФИАС** — Государственный адресный реестр, ведёт ФНС. Полная выгрузка (XML, ранее DBF) бесплатно скачивается с портала ФИАС. У каждого дома есть GUID (`HOUSEGUID` / `house_fias_id`), он совпадает в ФИАС и ГАР. ГАР содержит и административное, и муниципальное деление.

**DaData** — самый популярный коммерческий слой поверх ГАР:
- `suggest/address` — автокомплит с исправлением опечаток, неправильной раскладки, исторических названий («Питер» → «Санкт-Петербург»);
- `clean/address` — стандартизация «грязных» адресов из выгрузок провайдеров;
- `findById/address` — адрес по ФИАС-коду или кадастровому номеру.

В ответе нужны поля `house_fias_id` и `fias_level` (8 = найден до дома, 9 = до квартиры).

```python
import requests

API_KEY = "..."
r = requests.post(
    "https://suggestions.dadata.ru/suggestions/api/4_1/rs/suggest/address",
    headers={"Authorization": f"Token {API_KEY}", "Content-Type": "application/json"},
    json={
        "query": "спб просвещения 15 к2",
        "from_bound": {"value": "house"},
        "to_bound": {"value": "house"},
    },
)
for s in r.json()["suggestions"]:
    d = s["data"]
    print(s["value"], d["house_fias_id"], d["fias_level"], d["geo_lat"], d["geo_lon"])
```

⚠️ Подвох: ФИАС-коды домов **иногда меняются**. Нужно хранить историю кодов (или дополнительно кадастровый номер и координаты) и периодически перематчивать.

### 4.2. Слой покрытия

Минимальная модель данных (PostgreSQL):

```sql
CREATE TABLE houses (
    id           uuid PRIMARY KEY,          -- house_fias_id из ГАР
    city_fias_id uuid NOT NULL,
    street_fias_id uuid,
    address      text NOT NULL,             -- нормализованная строка
    house_type   text,                      -- МКД / частный
    geo          geography(Point, 4326),
    cadnum       text
);

CREATE TABLE providers (
    id        serial PRIMARY KEY,
    name      text NOT NULL,
    inn       text,
    is_partner boolean DEFAULT false       -- есть ли агентский договор
);

CREATE TABLE coverage (
    house_id    uuid REFERENCES houses(id),
    provider_id int  REFERENCES providers(id),
    technology  text,                       -- FTTB, GPON, DOCSIS, xDSL, 4G
    status      text,                       -- connected / planned / on_request
    source      text,                       -- partner_feed / api_check / lead_feedback / manual
    confidence  real,                       -- 0..1
    updated_at  timestamptz DEFAULT now(),
    PRIMARY KEY (house_id, provider_id, technology)
);

CREATE TABLE tariffs (
    id          serial PRIMARY KEY,
    provider_id int REFERENCES providers(id),
    city_fias_id uuid,                      -- тарифы обычно региональные
    technology  text,
    name        text,
    speed_mbps  int,
    price       numeric,
    promo_price numeric,
    promo_months int,
    has_tv      boolean,
    active      boolean DEFAULT true
);
```

Для частного сектора покрытие часто задаётся не списком домов, а **улицей целиком или полигоном** на карте — тогда проверка идёт через `ST_Contains` по координатам дома.

### 4.3. Откуда берутся данные о покрытии

| Источник | Как выглядит | Плюсы / минусы |
|---|---|---|
| **Выгрузки партнёров** | xlsx/csv/xml со списком домов, иногда API или KML-полигоны | Основной источник. Нужен агентский договор. Форматы у всех разные → большой ETL. |
| **Онлайн-проверка у провайдера** | API проверки техвозможности (дают не всем) или форма на сайте | Самые свежие данные, но медленно и без договора — хрупко. |
| **Обратная связь по заявкам** | Колл-центр/провайдер вернул «нет техвозможности» или «подключён» | Постоянно чистит базу, самый ценный сигнал качества. |
| **Отзывы и краудсорсинг** | «У нас в доме есть X» | Помогает с мелкими локальными операторами, но шумно. |
| **Реестр лицензий РКН** | Территория оказания услуг по лицензии | Только уровень региона — подходит, чтобы знать *кто вообще работает* в регионе. |
| **2ГИС / карты** | Офисы и зоны операторов | Для первичного списка провайдеров города. |

101 Интернет заявляет обновление тарифов, акций и адресных баз партнёров в течение суток, а по городским страницам — ежедневное обновление.

### 4.4. Поиск

1. Автокомплит → пользователь выбирает дом → получаем `house_fias_id`.
2. `SELECT` по `coverage` + `JOIN tariffs` по провайдеру, городу и технологии.
3. Сортировка (цена с учётом акции / без, скорость), фильтры (провайдер, ТВ, цена).
4. Если дом не найден в базе → показывают «всех провайдеров города» и предлагают оставить заявку («уточним вручную»). Это тоже лид.

### 4.5. Лидогенерация и статусы

- Форма: телефон + выбранный тариф + адрес (и квартира).
- CRM агрегатора → оператор КЦ перезванивает → заявка уходит провайдеру (API или агентский портал).
- Провайдер возвращает статусы: принята / назначен монтаж / подключён / отказ (нет техвозможности, клиент передумал, дубль).
- Статус «отказ: нет ТВ» → понижаем `confidence` в `coverage`.
- Антифрод: у операторов есть критерии фиктивных договоров, так что «накрутка» заявок не оплачивается.

### 4.6. SEO — главный канал трафика

Огромное число статических страниц: «Провайдеры интернета по адресу в <городе>», «<улица>: список подключённых домов», «<провайдер> в <городе>: тарифы», рейтинги и отзывы. Страницы генерируются из той же базы и содержат счётчики («доступно N тарифов, M провайдеров, данные на <дата>»).

## 5. Ограничения и проблемы

- **«Провайдер есть в доме» ≠ «можно подключиться».** Могут кончиться порты на коммутаторе, быть занят стояк, провайдер не заходит в конкретный подъезд. Поэтому финальную техвозможность подтверждает оператор при звонке.
- **Устаревание.** Провайдеры уходят из домов, сливаются (поглощения локальных сетей федералами), меняют бренды.
- **Малые города и частный сектор** — дыры в базе, мелкие операторы не участвуют в партнёрках.
- **Изменение ФИАС-кодов**, новостройки, которых ещё нет в ГАР.
- **Нормализация адресов** — самая трудоёмкая часть ETL (литеры, корпуса, строения, «уч.» в СНТ).

## 6. Если делать свой сервис

### Варианты входа

1. **Стать партнёром крупного агрегатора.** 101 Интернет прямо предлагает партнёрам готовые тарифные и адресные базы с обновлением, обработку лидов своим колл-центром и передачу статусов заявок по API. Самый быстрый старт — фактически white-label.
2. **Прямые агентские договоры** с МТС, Билайном, Ростелекомом, МегаФоном, Дом.ру + локальными операторами. Больше маржа, но нужно собирать и поддерживать базы самому.
3. **Парсинг сайтов провайдеров** («проверить адрес»). Технически возможно, но хрупко (капчи, антибот, блокировки VPN-трафика), противоречит условиям сайтов и без агентского договора не приносит денег.

### MVP по шагам

1. Выбрать 1 город, скачать ГАР по региону или взять DaData.
2. Договориться с 3–5 провайдерами (федералы + 1–2 местных), получить выгрузки домов.
3. ETL: `clean/address` → `house_fias_id` → `coverage`. Лог несматченных адресов на ручной разбор.
4. Фронт: автокомплит + выдача тарифов + форма заявки.
5. CRM/таблица лидов + передача провайдеру + статусы.
6. SEO-страницы по улицам и домам.

### Юридическое

- Телефон и адрес клиента — **персональные данные** (152-ФЗ): нужны согласие на обработку и на передачу провайдеру, политика обработки ПДн, уведомление Роскомнадзора как оператора ПДн.
- Сама перепродажа не требует лицензии связи — агрегатор действует как агент по договору с оператором, договор услуг связи клиент заключает с провайдером.
- Условия агентских оферт (сроки выплат, критерии фрода, запреты на определённую рекламу, например по бренду оператора) — читать до запуска.
