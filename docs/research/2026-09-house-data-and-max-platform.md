# Данные о состоянии дома, платформа MAX, карты и адреса

Исследование для MaxTown, 24.09.2026. Только первичные источники: официальная
документация, законы и приказы (consultant.ru), официальные порталы, исходный
код SDK и клиентов. Всё, что не удалось проверить по первичному источнику,
помечено **«не подтверждено»**. Часть порталов (dom.gosuslugi.ru, mosgorlift.ru,
mosvodokanal.ru, data.gov.spb.ru, online.moek.ru, portal.noc.gov.ru) из среды
исследования не открылась. Выводы по ним помечены отдельно.

## Главное

1. **Общероссийского открытого источника «что сейчас с домом» для стороннего
   приложения нет.** ГИС ЖКХ — единственная федеральная система, куда УК и РСО
   обязаны выкладывать плановые и аварийные перерывы
   ([приказ Минстроя 79/пр, п. 6.1–6.5](https://www.consultant.ru/document/cons_doc_LAW_471189/)).
   Подключаются к ней только поставщики информации, через ЕСИА и
   квалифицированные сертификаты ЭП
   ([приказ Минстроя 259/пр](https://www.consultant.ru/document/cons_doc_LAW_506931/f810e857d3bd1265c9e3a7f892c14ed3b0074efe/)).
   Открытого API для чтения чужих домов не найдено (не подтверждено: портал не
   открылся).
2. **Самый пригодный автоматический источник — набор data.mos.ru № 1401
   «График отключения горячей воды».** Данные идут от МОЭК, в наборе 72 353
   строения, последний релиз от 22.09.2026, есть поле UNOM. Доступ через API с
   `api_key` ([метаданные](https://data.mos.ru/api/v2/odata/datasets/1401)).
   Покрывает только Москву и только плановые отключения горячей воды.
3. **Свет, холодная вода, отопление, лифты и интернет автоматически не
   получить.** Россети МР публикуют плановые отключения только
   HTML-таблицами с адресом свободным текстом
   ([rossetimr.ru](https://rossetimr.ru/client/disconnection/)). Публичного
   API статуса у интернет-провайдеров не найдено. Эти данные вносят люди: УК,
   староста дома, жильцы.
4. **Для хакатона главный риск — регистрация в MAX.** Разместить бота и
   мини-апп может только верифицированное юрлицо, ИП или самозанятый —
   резидент РФ ([документация](https://dev.max.ru/docs/maxbusiness/connection)).
   Модерация бота занимает до 48 часов в рабочие дни
   ([документация](https://dev.max.ru/docs/chatbots/bots-create/create)).
   Бота нужно заводить заранее или получить у организаторов.
5. **`initData` подписан так же, как в Telegram.** Ключ:
   `secret = HMAC-SHA256(key="WebAppData", msg=BOT_TOKEN)`, затем
   `hex(HMAC-SHA256(secret, отсортированные "k=v" через \n))`. MAX
   рекомендует считать данные устаревшими через 1 час. Телефона в `initData`
   нет, его запрашивают через `requestContact()`, ответ проверяется по hash
   ([валидация](https://dev.max.ru/docs/webapps/validation),
   [Bridge](https://dev.max.ru/docs/webapps/bridge)).
6. **QR-приглашение в квартиру делается диплинком
   `https://max.ru/<бот>?startapp=<payload>`.** Payload — до 512 символов из
   `[A-Za-z0-9_-]`. Значение приходит в `start_param`. Документация прямо
   советует класть туда одноразовый токен, а не данные
   ([документация](https://dev.max.ru/docs/webapps/introduction)).
7. **`WebApp.ready()` существует** — это противоречит `AGENTS.md`. Метод есть
   в боевом скрипте `max-web-app.js` и обрабатывается веб-клиентом. Он не
   документирован и не обязателен: веб-клиент считает приложение готовым уже
   по `onload` iframe. В веб-клиенте мини-апп открывается в `credentialless`
   iframe. Там **нет** QR-сканера, хаптики, DeviceStorage и SecureStorage.
8. **Bot API работает на `platform-api2.max.ru` с сертификатом Минцифры.**
   Node без `NODE_EXTRA_CA_CERTS` падает с `UNABLE_TO_GET_ISSUER_CERT_LOCALLY`
   (проверено на Node 26). Вебхук принимается только по HTTPS на порту 443.
   Лимиты: 30 запросов в секунду на API и 2 сообщения в секунду в один чат.
   **Юридический риск:** Требования платформы запрещают слать через API
   «сервисные сообщения» — в том числе о статусах — без договора с MAX
   ([п. 1.5](https://dev.max.ru/docs/legal/requirements)).
9. **Карта для демо: MapLibre или Leaflet на тайлах OSM (OpenFreeMap).
   Точки «рядом» заранее выгружаем через Overpass и храним у себя.** ODbL
   разрешает хранить данные с атрибуцией. Бесплатный тариф Яндекса запрещает
   сохранять полученные данные и требует открытого доступа к проекту. Поиск по
   организациям у Яндекса только платный. Демо-ключ 2ГИС действует месяц и даёт
   1000 запросов к Places.
10. **Уникальный ID Дома — ГАР-GUID дома из подсказок DaData
    (`data.house_fias_id` при `fias_level = "8"`).** DaData бесплатно даёт
    10 000 запросов в сутки и работает по CORS
    ([DaData](https://dadata.ru/api/suggest/address/)). Официальный API ФИАС
    бесплатен, но заявку на мастер-токен рассматривают до 30 дней
    ([условия](https://fias.nalog.ru/docs/%D0%A3%D1%81%D0%BB%D0%BE%D0%B2%D0%B8%D1%8F%20%D0%B8%D1%81%D0%BF%D0%BE%D0%BB%D1%8C%D0%B7%D0%BE%D0%B2%D0%B0%D0%BD%D0%B8%D1%8F%20API-%D1%81%D0%B5%D1%80%D0%B2%D0%B8%D1%81%D0%BE%D0%B2%20%D0%A4%D0%98%D0%90%D0%A1.pdf)).
    Геокодеры Яндекса и 2ГИС запрещают хранить результат, поэтому как источник
    постоянного ID не годятся.

## 1. Откуда автоматически брать данные о состоянии дома

### 1.1. Что УК и РСО обязаны публиковать по закону

- **ГИС ЖКХ** работает по [209-ФЗ](https://www.consultant.ru/document/cons_doc_LAW_165810/).
  Информация в системе официальная и составляет государственный
  информационный ресурс
  ([ст. 9](https://www.consultant.ru/document/cons_doc_LAW_165810/0aac1906aadd7a20dc42abd5567172013a5dde26/)).
- **Приказ 74/114/пр от 2016 года утратил силу**
  ([КонсультантПлюс](https://www.consultant.ru/document/cons_doc_LAW_198895/),
  отменён приказом [688/577/пр](https://www.consultant.ru/document/cons_doc_LAW_458836/)).
  Сейчас действует **приказ Минстроя от 07.02.2024 № 79/пр** в редакции от
  30.06.2026, срок действия до 01.09.2030
  ([текст](https://www.consultant.ru/document/cons_doc_LAW_471189/)).
- **Что размещает УК, ТСЖ или ЖСК — исполнитель коммунальных услуг** (раздел 6):
  - 6.1 — плановый перерыв: адрес, плановые начало и конец. Срок — не позднее
    сроков информирования жильцов по законодательству
    ([п. 6.1](https://www.consultant.ru/document/cons_doc_LAW_471189/0043d229d1e26d73e8cfd39d95d59e3f62f0f27f/)).
  - 6.2 — приостановление или ограничение услуги.
  - 6.3 — внеплановый перерыв (авария): адрес, начало, плановое окончание,
    причина, фактическое окончание. Фактическое окончание вносится не позднее
    7 дней после окончания перерыва
    ([п. 6.3](https://www.consultant.ru/document/cons_doc_LAW_471189/d74a98115db98769295c8e89fe82747a8dfe36f2/)).
  - 6.4 — услуги ненадлежащего качества; 6.5 — рассмотрение обращений по
    авариям.
  - Разделы 4.1–4.5 содержат то же самое для РСО, которые сами являются
    исполнителями.
- **Сроки информирования жильцов** задаёт [ПП РФ № 354, п. 31](https://www.consultant.ru/document/cons_doc_LAW_114247/fe4565bc56b765620bfaaf0155a4f389e6d47371/):
  - п. «н»: о плановом перерыве — не позднее чем за 10 рабочих дней;
  - п. «м»: о причинах и предполагаемой продолжительности перерывов сверх
    нормы — «в порядке и сроки», установленные Правилами.
- **Вывод для продукта.** Структура ГИС ЖКХ «адрес — начало — плановое
  окончание — причина — фактическое окончание» — готовая модель
  `Отключения` для MaxTown. УК и так обязана заполнять эти поля, значит,
  панель УК может просить то же самое.

**API data.mos.ru.** Официальная спецификация OpenAPI лежит на портале
([api-swagger-opod.yaml](https://data.mos.ru/assets/api-swagger-opod.yaml)):
- базовый адрес `https://apidata.mos.ru/v1`;
- ключ передаётся параметром `api_key` в query;
- `/datasets/{id}/rows` поддерживает `$top`, `$skip`, `$orderby`, `$filter`;
- не больше 1000 записей за запрос.

Без ключа сервер отвечает `401 «Необходимо указать api_key»`, с неверным
ключом — `403` (проверено). Ключ выдаётся в личном кабинете data.mos.ru после
входа через mos.ru: в коде портала есть эндпоинты `/odataUsers/apiKey` и
`/odataAuth/authSudir`. Страница для разработчиков —
[data.mos.ru/developers](https://data.mos.ru/developers). Сколько времени
занимает выдача ключа и лицензия данных — **не подтверждено**.

**Вердикт по № 1401: пригодно сразу.** Карточку «Горячая вода: отключение с …

### 1.6. Лифты

- Правила безопасного использования лифтов:
  [ПП РФ № 1744 от 20.10.2023](https://www.consultant.ru/document/cons_doc_LAW_460399/91c867f29dfa19e576d8a55a4f732a4f38108517/),
  заменило ПП № 743. В них есть понятие «система диспетчерского
  (операторского) контроля» — дистанционный контроль работы лифта и
  переговорная связь с диспетчерским пунктом. Владелец обязан организовать её
  обслуживание.
- Значит, состояние лифта известно диспетчерской службе (УК или
  специализированной организации). Публичного API операторов, в том числе
  Мосгорлифта, найти не удалось: mosgorlift.ru не открылся — **не
  подтверждено**.
- **Вердикт: лифты — только от людей** (УК, диспетчер, жильцы).

### 1.8. IoT, умный дом и приборы учёта

- **Электроэнергия.** [ПП РФ № 890](https://www.consultant.ru/document/cons_doc_LAW_355626/)
  определяет минимальный набор функций интеллектуальных систем учёта и порядок
  доступа к ним. Доступ получают участники отношений — потребитель, УК,
  сетевая компания. У стороннего приложения прав нет, данные доступны только
  через УК или потребителя.
- **Тепло и вода (ИТП, узлы учёта), протоколы диспетчеризации лифтов** —
  закрытые системы подрядчиков. Конкретные протоколы в рамках исследования не
  проверялись — **не подтверждено**.
- **Вердикт: для хакатона нереалистично.**

**Что подключить после демо (1–2 источника):**
1. **data.mos.ru № 1401**: API, свежие данные, ID строения, официальный

### 2.1. Кто может создать мини-апп и как он привязывается

- **Как привязать мини-апп:** business.max.ru → «Чат-боты» → ⋮ → «Настройки»

  Верить документации.

### 2.2. Требования к URL, хостингу и встраиванию

- **URL мини-аппа** ([документация](https://dev.max.ru/docs/webapps/introduction)):
  - не длиннее 1024 символов;
  - только `https://`;
  - допустимые символы — латиница, цифры, точка и дефис; пробелы запрещены.
    Буквально это исключает `/` и `:`, так что, видимо, речь о хосте. Путь
    в URL — **не подтверждено**.
- Ограничений на домен, порт и сертификат мини-аппа в документации нет —
  **не подтверждено**.
- **Встраивание в веб-клиент** (web.max.ru). Выводы сделаны по исходному коду
  бандла `/_app/immutable/chunks/B10WO7G9.js`; имя файла меняется при
  релизах.
  - Мини-апп грузится в `<iframe>` с атрибутами
    `allow="camera; microphone; geolocation; clipboard-write;"`,
    `sandbox="allow-scripts allow-same-origin allow-popups allow-forms allow-modals allow-storage-access-by-user-activation allow-downloads"`,
    `referrerpolicy="strict-origin"` и **`credentialless`**.
  - Практически это значит:
    - сайт мини-аппа нельзя отдавать с `X-Frame-Options: DENY` или
      `Content-Security-Policy: frame-ancestors`, не включающим
      `https://web.max.ru`;
    - в credentialless-iframe cookies и хранилище эфемерны. Авторизацию
      строим на `initData` → токен в памяти и заголовке, а не на cookie. Это
      вывод из семантики `credentialless`, в документации MAX о нём ничего нет.
  - Сообщения от мини-аппа принимаются только с origin его URL.
  - Стиль iframe получает `color-scheme` темы MAX.
  - Если за 15 секунд нет ни `onload`, ни `WebAppReady`, клиент показывает
    экран ошибки.
- **Мобильные клиенты** используют транспорт `window.WebViewHandler.postEvent`
  ([max-web-app.js](https://st.max.ru/js/max-web-app.js), Last-Modified
  09.09.2026). Подробности WebView — **не подтверждено**.
- **Хостинг.** Документация предлагает VK Cloud, GitHub Pages и Yandex Cloud.
  Требование одно — HTTPS.

### 2.3. Локальная разработка и тестирование

- **Отдельного dev- или test-режима и песочницы в документации нет.** Тест
  идёт на настоящем боте, который прошёл модерацию.
- **Туннели в документации MAX не упоминаются** — **не подтверждено**. Хосты
  вида `xxx.trycloudflare.com` и `xxx.ngrok-free.app` формально подходят под
  требования к URL.
  - **Cloudflare Quick Tunnel** — только для тестов: случайный поддомен,
    не больше 200 одновременных запросов, без SSE
    ([Cloudflare](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/trycloudflare/)).
  - **ngrok Free** показывает промежуточную страницу для HTML-трафика. Её
    отключают cookie на 7 дней или заголовок `ngrok-skip-browser-warning`
    ([ngrok](https://ngrok.com/docs/pricing-limits/free-plan-limits/)). При
    первой загрузке заголовок не передать, а cookie в credentialless-iframe
    эфемерна. Вывод: **ngrok Free для мини-аппа неудобен, лучше cloudflared**.
  - **tuna.am, xtunnel** — **не проверялись**.
- **Vite (v8 в `apps/miniapp`)** отвечает только разрешённым хостам. Хост
  туннеля нужно добавить в `server.allowedHosts`
  ([Vite](https://vite.dev/config/server-options#server-allowedhosts)).
- **Проверять можно в браузере на ПК через web.max.ru.** Платформа `web`
  поддерживается ([Bridge](https://dev.max.ru/docs/webapps/bridge)),
  встраивание описано в 2.2. Но часть Bridge в вебе не работает (2.6), а
  DevTools видят iframe.
- **Вне MAX** `window.WebApp.initData` равен `null`, события уходят в
  `console.warn` ([исходник](https://st.max.ru/js/max-web-app.js)). Для
  разработки на `localhost` нужен мок `initData`, подписанный тестовым
  токеном на бэкенде.
- **Вебхук бота нельзя повесить на localhost или порт ≠ 443** (2.7). Для
  разработки используем long polling: он разрешён на этапе разработки и
  тестирования ([FAQ](https://dev.max.ru/help/events)).

### 2.4. `initData`: формат и проверка

- **Где лежат данные.** MAX передаёт их во фрагменте URL:
  `#WebAppData=<urlencoded>&WebAppPlatform=web&WebAppVersion=26.2.8`.
  `window.WebApp.initData` — строка `WebAppData`
  ([валидация](https://dev.max.ru/docs/webapps/validation)).
- **Поля внутри:**

  | Поле | Что это |
  |---|---|
  | `auth_date` | unix-время в секундах |
  | `query_id` | идентификатор сессии |
  | `ip` | IP пользователя, может отсутствовать |
  | `user` | JSON: `id`, `first_name`, `last_name`, `username`, `language_code`, `photo_url` |
  | `chat` | JSON: `id`, `type` = `DIALOG`, `CHAT` или `CHANNEL` |
  | `start_param` | параметр запуска |
  | `hash` | подпись |

  Источник: [Bridge](https://dev.max.ru/docs/webapps/bridge). **Телефона в
  `initData` нет.**
- **Алгоритм проверки** ([валидация](https://dev.max.ru/docs/webapps/validation)):
  1. Разбить `WebAppData` по `&` на пары `key=value`. Каждый ключ должен
     встречаться ровно один раз, `hash` — ровно один.
  2. Сохранить `hash` и исключить его из пар.
  3. URL-декодировать значения.
  4. Отсортировать пары по ключу, a → z.
  5. Склеить строку `launch_params = "k1=v1\nk2=v2…"`.
  6. `secret_key = HMAC-SHA256(key = "WebAppData", message = BOT_TOKEN)`. В
     эталонном TS-коде `importKey("WebAppData")`, затем `sign(botToken)` —
     как в Telegram.
  7. `hash' = hex(HMAC-SHA256(key = secret_key, message = launch_params))`.
  8. Сравнить с `hash`.
- **Свежесть.** `auth_date` — «время выдачи данных… рекомендуемый интервал
  составляет 1 час» ([Bridge](https://dev.max.ru/docs/webapps/bridge)).
  Отвергаем старше часа.
- **Замечания к реализации:**
  - эталонный код режет пары через `x.split('=')`, и значения с `=`
    обрезаются. Резать надо по первому `=`;
  - `WebAppVersion` и `WebAppPlatform` в подпись не входят.
- **`start_param` в подписи.** Скрипт Bridge разбирает `start_param` внутри
  `WebAppData`, значит, он, вероятно, подписан. В примере из документации
  его нет — **проверить на живом запуске**. Параллельно значение приходит
  неподписанным GET-параметром `WebAppStartParam`
  ([документация](https://dev.max.ru/docs/webapps/introduction)). Доверяем
  только значению из проверенного `initData`.

### 2.5. Диплинки и `start_param` для QR-приглашений

- **Мини-апп:** `https://max.ru/<botName>?startapp=<payload>`. Payload
  необязательный, не длиннее 512 символов из `A–Z a–z 0–9 _ -`. Если длиннее
  или с другими символами, payload **удаляется**. В приложении значение
  читается из `initDataUnsafe.start_param`, строкой — из `initData`
  ([документация](https://dev.max.ru/docs/webapps/introduction)).
- **Бот:** `https://max.ru/<botName>?start=<payload>`, до 128 символов.
  Приходит событием `bot_started` с полем `payload`
  ([подготовка](https://dev.max.ru/docs/chatbots/bots-coding/prepare)).
- **Минимальные версии клиентов** для диплинков: iOS 2.7.0, Android 2.9.0
  ([FAQ](https://dev.max.ru/help/deeplinks)).
- **Прямое указание MAX:** «Не передавайте в payload конфиденциальные данные
  в открытом виде — используйте одноразовые токены».
- **Схема для MaxTown:**
  - QR = `https://max.ru/id<ИНН>_bot?startapp=inv_<22 символа base64url>`.
    Для 128 бит случайности хватит 22 символов.
  - На бэкенде токен → квартира, срок жизни, одноразовость.
  - Никнейм бота с ИНН известен только после создания бота. Базовый URL QR
    держим в конфиге.
- **Кнопка `open_app` в сообщении бота** принимает
  `web_app` (публичное имя бота, обязательно), `contact_id` и `payload`
  (`^[\w-]*$`, до 512)
  ([OpenAPI](https://github.com/max-messenger/api-schema/blob/main/schema.yaml)).
  Так бот может прислать жильцу кнопку «Открыть заявку №…».
- **Шеринг ссылки-приглашения:** `https://max.ru/:share?text=…` на iOS,
  Android и в вебе; на десктопе — в разработке. Второй вариант —
  `WebApp.shareMaxContent`.

### 2.7. Bot API: уведомления, вебхуки, лимиты

- **Базовый адрес и авторизация.** База — `https://platform-api2.max.ru`,
  токен — в заголовке `Authorization: <token>`; query-параметр больше не
  поддерживается ([обзор API](https://dev.max.ru/docs-api)).
  `@maxhub/max-bot-api` 0.3.1 уже ходит на `platform-api2`
  (`dist/core/network/api/client.js`).
- **Сертификат Минцифры.** API сам использует сертификат `Russian Trusted
  Sub CA`, проверено `openssl s_client`. Документация просит «добавить
  сертификат Минцифры в список доверенных». Проверено на Node 26:
  - без корня `fetch` падает с `UNABLE_TO_GET_ISSUER_CERT_LOCALLY`;
  - с `NODE_EXTRA_CA_CERTS=russian_trusted_root_ca.pem` запрос проходит.
  - Корневой сертификат —
    [gosuslugi.ru/crt](https://www.gosuslugi.ru/crt), прямой файл
    `https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt`.
- **Вебхук** ([POST /subscriptions](https://dev.max.ru/docs-api/methods/POST/subscriptions)):
  - только HTTPS и только порт 443, порт в URL не указывается;
  - сертификат доверенного УЦ или Минцифры, полная цепочка, домен совпадает
    с CN или SAN; самоподписанные с 25.05.2026 не принимаются;
  - ответ 200 в течение 30 секунд;
  - до 10 повторов через 60 с, затем ×2,5; если 8 часов нет успеха, подписка
    снимается;
  - `secret` (`^[a-zA-Z0-9_-]{5,256}$`) приходит в заголовке
    `X-Max-Bot-Api-Secret`.
- **Long polling** ([GET /updates](https://dev.max.ru/docs-api/methods/GET/updates)):
  - только для разработки и тестирования;
  - одновременно с вебхуком не работает;
  - `limit` 1–1000, `timeout` 0–90 с.
- **Лимиты** ([подготовка](https://dev.max.ru/docs/chatbots/bots-coding/prepare),
  [POST /messages](https://dev.max.ru/docs-api/methods/POST/messages)):
  - 30 запросов в секунду на `platform-api2`;
  - не больше 2 сообщений в секунду в один чат;
  - текст до 4000 символов;
  - inline-клавиатура: до 210 кнопок, 30 рядов, 7 кнопок в ряду; для `link`,
    `open_app`, `request_contact`, `request_geo_location` — до 3 в ряду
    ([клавиатура](https://dev.max.ru/docs-api/use-cases/sending-messages/keyboard)).
- **Написать пользователю.** `POST /messages?user_id=…`; в SDK —
  `bot.api.sendMessageToUser(userId, text)`.
  - Может ли бот написать тому, кто открыл мини-апп, но не нажимал «Старт», —
    **не подтверждено**: ни документация, ни OpenAPI этого не описывают.
  - Совпадает ли `initData.user.id` с `user_id` в Bot API — **не
    подтверждено** (вероятно, да).
  - Надёжный путь: при первом входе попросить жильца открыть чат с ботом и
    нажать «Старт» (событие `bot_started`,
    [Update](https://dev.max.ru/docs-api/objects/Update)).
  - Отследить, включены ли у пользователя уведомления, нельзя
    ([FAQ](https://dev.max.ru/help/chatbots)).
- **⚠️ Правила платформы.** Приложениям запрещено использовать API «для
  формирования, передачи или отправки Авторизационных… Транзакционных… и
  Сервисных сообщений… за исключением случаев, прямо предусмотренных
  Договором» ([Требования, п. 1.5](https://dev.max.ru/docs/legal/requirements)).
  «Сервисные сообщения» определены как сообщения «о событиях, статусах и (или)
  действиях, связанных с использованием услуг»
  ([Правила](https://dev.max.ru/docs/legal/rules)). Уведомление «ваша заявка
  выполнена» формально под это подпадает. **Уточнить у организаторов или
  MAX**, разрешены ли такие уведомления в рамках хакатона.
- **Персональные данные.** Разработчик — самостоятельный оператор ПДн и
  обязан опубликовать политику и условия
  ([Правила, раздел 4](https://dev.max.ru/docs/legal/rules)). Телефон из
  `requestContact` разрешено использовать только для этого мини-аппа
  ([Bridge](https://dev.max.ru/docs/webapps/bridge)).

### 2.8. Фото к заявке

- **Документация.** Про `<input type="file">` и камеру в мини-аппе ничего
  не сказано — **не подтверждено**.
- **Веб-клиент.** В iframe есть `allow="camera…"` и `sandbox allow-forms`
  (2.2). Выбор файла там должен работать — вывод из атрибутов, не проверено.
- **Мобильные WebView** — **не подтверждено**, проверить на устройстве в
  первый же день.
- **Запасной путь, который точно работает.** Жилец отправляет фото в чат с
  ботом, бот получает `message_created` с вложением `image`
  ([Update](https://dev.max.ru/docs-api/objects/Update),
  [POST /messages](https://dev.max.ru/docs-api/methods/POST/messages)). Для
  исходящих файлов у бота есть `POST /uploads`.

**Вердикт для демо: OSM-стек.**
- MapLibre GL JS + стиль OpenFreeMap. Бесплатно, без ключа, работает в
  iframe.
- «Места рядом»: при регистрации Дома бэкенд один раз делает Overpass-запрос
  в радиусе ~1 км по нужным тегам и сохраняет POI в Postgres с атрибуцией
  «© OpenStreetMap contributors». Это разрешено ODbL и укладывается в
  «регулярное» ограничение Overpass — меньше 100 запросов в сутки.
- Nominatim для автодополнения адреса **нельзя**: это запрещено его
  политикой. Адрес берём из DaData, см. раздел 4.

Яндекс привлекательнее по качеству POI в России. Но бесплатно нельзя ни
хранить результаты, ни искать организации. 2ГИС годится как краткий
эксперимент на демо-ключе (месяц, 1000 запросов к Places), но не как основа.

## 4. Реестр адресов для регистрации Дома

### 4.1. ГАР / ФИАС (fias.nalog.ru)

- **ГАР — открытый общедоступный источник.** Портал называет ГАР
  «единственным легитимным источником сведений об адресе»
  ([fias.nalog.ru](https://fias.nalog.ru/)).
- **Файловые выгрузки:**
  - полная `gar_xml.zip` и дельта `gar_delta_xml.zip`;
  - последняя версия от 22.09.2026, выходят дважды в неделю — 04, 08, 11,
    15, 18, 22 сентября
    ([GetLastDownloadFileInfo](https://fias.nalog.ru/WebServices/Public/GetLastDownloadFileInfo),
    [GetAllDownloadFileInfo](https://fias.nalog.ru/WebServices/Public/GetAllDownloadFileInfo));
  - XSD-схемы: [gar_schemas.zip](https://fias.nalog.ru/docs/gar_schemas.zip);
  - формат КЛАДР 4.0 ещё выкладывается.
- **Стабильные идентификаторы дома** (`AS_HOUSES`, XSD 2.251.08):
  - `OBJECTID` — «глобальный уникальный идентификатор объекта типа INTEGER»;
  - `OBJECTGUID` — «глобальный уникальный идентификатор адресного объекта
    типа UUID»;
  - `ID` — ключ **записи** и меняется с историей, как и `PREVID`/`NEXTID`.
    Для MaxTown ключ — `OBJECTGUID`.
- **API** ([раздел «Разработчикам» → «API-сервисы»](https://fias.nalog.ru/Frontend),
  [Swagger](https://fias-public-service.nalog.ru/api/spas/v2.0/swagger/index.html)):
  - сервисы «Адресная строка» (поэлементный ввод, подсказки, полнотекстовый
    поиск), «Конвертация КЛАДР→ГАР», «Получение изменений»;
  - бесплатно, но нужен **мастер-токен**: заявка на `api.fias@tax.gov.ru`
    с ОГРН или ОГРНИП, URL ресурса и не больше 10 IP-адресов;
  - рассмотрение **до 30 дней**; лимит 100 запросов в минуту и 10 000 в
    сутки;
  - условия: [PDF](https://fias.nalog.ru/docs/%D0%A3%D1%81%D0%BB%D0%BE%D0%B2%D0%B8%D1%8F%20%D0%B8%D1%81%D0%BF%D0%BE%D0%BB%D1%8C%D0%B7%D0%BE%D0%B2%D0%B0%D0%BD%D0%B8%D1%8F%20API-%D1%81%D0%B5%D1%80%D0%B2%D0%B8%D1%81%D0%BE%D0%B2%20%D0%A4%D0%98%D0%90%D0%A1.pdf).
  - Спецификация Swagger без токена отдаёт 403.
- **СМЭВ** — виды сведений для госорганов, не для нас.
- **Вердикт:** API к хакатону не успеть. Выгрузка ГАР годится после демо для
  своей проверки адресов, но это десятки гигабайт XML — объём **не
  проверялся**.

### 4.2. DaData, подсказки по адресам

- **Эндпоинт:** `POST https://suggestions.dadata.ru/suggestions/api/4_1/rs/suggest/address`
  с заголовком `Authorization: Token <API_KEY>`. В официальном примере
  `mode: "cors"`, то есть вызов прямо из браузера
  ([документация](https://dadata.ru/api/suggest/address/)).
- **Бесплатно:** 10 000 запросов в сутки суммарно на все виды подсказок.
  После регистрации включается тариф «как Лёгкий», КЛАДР-, ФИАС- и ГАР-коды
  есть на всех тарифах ([тарифы](https://dadata.ru/pricing/)). Ограничение
  частоты — ответ 429; конкретное число — **не подтверждено**.
- **Поля ответа:**
  - `data.house_fias_id` — ФИАС-код дома;
  - `data.fias_id` — «ФИАС-код (он же код ГАР)»;
  - `data.fias_level`: `8` — дом, `7` — улица, `65` — планировочная
    структура, `75` — участок;
  - `data.fias_actuality_state`;
  - `geo_lat`/`geo_lon` с `qc_geo` на всех тарифах; `house_flat_count` —
    только на «Максимальном».
- **Хранение результатов.** Оферта DaData — PDF-скан
  ([dadata.ru/terms](https://dadata.ru/terms/)), текст не извлекается.
  Ограничения на хранение — **не подтверждено**. Сам ФИАС-ID — идентификатор
  из открытого госреестра.
- **Вердикт: основной вариант для демо.**

### 4.3. Геокодеры Яндекса и 2ГИС как альтернатива

- **Яндекс:** Геокодер бесплатно даёт 1000 запросов в сутки. Сохранять
  результаты нельзя, кроме кэша на 30 дней, и показывать их на картах третьих
  лиц тоже нельзя ([условия, 5.1.5 и 6.6](https://yandex.ru/legal/maps_api/ru/)).
  ФИАС-кодов в ответе нет — **не проверялось**.
- **2ГИС:** хранить результаты геокодирования нельзя, кроме кэша
  ([соглашение, 4.2](https://law.2gis.ru/api-rules)). Демо-ключ даёт 1000
  запросов.
- **Вердикт:** как источник постоянного ID Дома **не годятся** по условиям
  использования.

### 4.4. Бонус для Москвы

- В data.mos.ru есть `UNOM`, «код адреса по АР» (адресный реестр Москвы).
  Хранить его рядом с ГАР-GUID — тогда отключения ГВС (№ 1401) сопоставляются
  с Домом без нечёткого поиска по адресу.
- Как сопоставить ГАР и UNOM автоматически — **не подтверждено**. Можно по
  нормализованному адресу.

### 4.5. Вердикт для демо

- **Регистрация Дома:**
  1. Поле адреса на DaData Suggest (вызов из мини-аппа, ключ публичный
     «Token»).
  2. Требуем `fias_level === "8"` и непустой `house_fias_id`.
  3. В Postgres — `UNIQUE (gar_house_guid)`. Повторная регистрация
     возвращает «Дом уже есть, попросите приглашение у старосты».
- **Нет `house_fias_id`** (новостройка ещё не в ГАР) — заявка на ручную
  проверку. Этот сценарий на демо можно не делать.
- **После демо:**
  - перепроверять GUID по дельтам ГАР: `ISACTUAL` и `ISACTIVE`, перенос
    через `NEXTID`;
  - или подать заявку на API ФИАС.

## Открытые вопросы и неподтверждённое

1. **ГИС ЖКХ.** Есть ли в открытых данных отключения и аварии, в каком
   формате, есть ли публичный API для чтения. dom.gosuslugi.ru из среды
   исследования не открылся.
2. **MAX, бот пишет первым.** Может ли бот написать пользователю, который
   открыл мини-апп, но не нажимал «Старт». Совпадает ли `initData.user.id` с
   `user_id` в Bot API.
3. **MAX, уведомления о заявках.** Разрешены ли они с учётом п. 1.5
   Требований о «сервисных сообщениях», если нет отдельного договора с MAX.
4. **MAX, аккаунт для хакатона.** Есть ли у организаторов бот или
   верифицированная организация. Иначе нужен ИП или самозанятый в команде и
   до 48 рабочих часов модерации.
5. **MAX, подпись `start_param`.** Входит ли он в подписанный `WebAppData`
   — проверить на живом запуске.
6. **MAX, телефон.** Точная формула проверки `hash` из `requestContact()`:
   порядок аргументов HMAC, формат `authDate` — проверить.
7. **MAX, повторная модерация.** Вызывает ли её смена URL мини-аппа.
   Допустим ли путь в URL, учитывая требование «латиница, цифры, точка,
   дефис».
8. **MAX, фото.** Работают ли `<input type="file">` и камера в мобильных
   WebView MAX.
9. **MAX, тема в мобильных клиентах.** Как передаётся тема: следует ли
   `prefers-color-scheme` за темой MAX в WebView.
10. **data.mos.ru, условия.** Процедура и сроки выдачи `api_key`, лицензия
    данных.
11. **Россети МР и соседи.** Есть ли у Россети МР машиночитаемый фид
    отключений за HTML. Данные Мосводоканала, Водоканала СПб, ТЭК СПб,
    Ленэнерго и МОЭК-бота в MAX: сайты не открылись.
12. **Лифты, интернет, умные счётчики.** Публичные API операторов
    диспетчеризации лифтов (Мосгорлифт и другие), ЦМУ ССОП
    (portal.noc.gov.ru), протоколы ИТП и счётчиков.
13. **DaData, условия.** Разрешено ли по оферте хранить ответы и какой
    лимит в секунду.
14. **Яндекс, открытый доступ.** Считается ли обязательный аккаунт MAX
    «особым требованием к регистрации», которое закрывает бесплатный JS API.
15. **OSM, полнота.** Насколько полно в OSM размечены поликлиники, МФЦ и
    отделения полиции в целевом районе.
