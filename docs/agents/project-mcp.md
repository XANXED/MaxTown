# MaxTown Project MCP

Локальный read-only MCP-сервер даёт Codex доступ к правилам и знаниям проекта.
Он читает только `AGENTS.md`, `CONTEXT.md`, `design/AGENTS.md` и Markdown-файлы
из `docs/adr/` и `docs/research/`. Исходники приложений, `.env` и другие данные
не читаются. Сервер не использует сеть и секреты.

## Подключение

Нужен Node.js 24 или новее и npm. После `npm install` Codex обнаруживает сервер
из `.codex/config.toml`, если репозиторий отмечен как доверенный. Конфигурация
запускает `npm run mcp:project` через stdio; отдельные токены и переменные среды
не нужны. После изменения конфигурации перезапустите Codex или обновите список
подключений MCP и проверьте, что `maxtown_project` отображается как подключённый.

Проверить сервер локально можно командой:

```bash
npm run smoke:mcp
```

Команда запускает реальный дочерний stdio-процесс, запрашивает ресурсы и
инструменты, читает словарь и корректно закрывает соединение.

## Ресурсы

- `maxtown://context/glossary` — `CONTEXT.md`, определения и Avoid-формулировки.
- `maxtown://project/rules` — корневой `AGENTS.md` и `design/AGENTS.md`.
- `maxtown://decisions` — Markdown-решения из `docs/adr/`.

## Инструменты

- `search_project_knowledge({ query, areas? })` — буквальный поиск по словам.
  `areas` принимает `glossary`, `decisions`, `research` и `rules`. Результаты
  включают путь источника, номер строки и короткий фрагмент.
- `check_domain_language({ text })` — находит термины из списков `_Avoid_:` в
  `CONTEXT.md` и возвращает рекомендуемый канонический термин с определением.
  Форматные ошибки словаря выводятся явно; сервер не угадывает термины.

Сервер сообщает пути источников и ошибки чтения. Если MCP недоступен, читайте
те же файлы напрямую: `CONTEXT.md`, `AGENTS.md`, `design/AGENTS.md`, `docs/adr/`
и `docs/research/`. Эти документы остаются источниками истины.
